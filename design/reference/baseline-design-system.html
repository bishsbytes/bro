A quiet instrument, not a coach.

Baseline is the design language for a health tracker built for men who won't be shouted at. Every reading is shown against the range that is normal for you — never against a target, a rival, or a streak.

Principles

Six rules that settle most arguments

Show the band, not the verdict

Health data is only meaningful relative to a person's own history. The gauge is the system's signature component and the default way to show any number. Avoid grades, scores out of 100, and traffic lights.

One big number per screen

At 56px, the metric type size is a scarce resource. If two things compete for it, the screen is doing two jobs and should be two screens.

Colour names a domain, never a judgement

Green means body, not good. Amber means load, not warning. The user's accent means you touched this. Three separate jobs, three separate sets of colour, never mixed — which is what lets the palette stay muted.

Logging takes one tap or it doesn't happen

Men under-report. Every input has a default, nothing is required, and a half-finished entry is still saved. Never block on a missing field.

Lines before shadows

Depth comes from hairlines and a single raised surface. No drop shadows, no gradient washes, no glassmorphism. The interface should read as printed.

Serif for their words, sans for our numbers

Anything a person writes or reads reflectively is set in the serif. Anything measured is set in the grotesque. The split is a promise about who is talking.

Accent

The one colour the user owns

Personal accents usually break a muted system, because people pick saturated colours and the palette stops being quiet. Baseline avoids that by letting the user choose hue only. Lightness and chroma are fixed by the system, so every possible choice lands inside the same muted range and passes contrast in both themes. There is no wrong answer available.

Implementation

Store a single integer, accentHue 0–360, on the user record — not a hex value. Hex would freeze one theme's rendering and break dark mode. Set it as a custom property on the root element and let CSS derive the rest; changing themes or adding a token later needs no migration. Default is 235, the harbour blue, so a user who never opens settings gets a considered choice rather than a random one. If you need to support engines without OKLCH, ship the seven presets as static hex and hide the slider.

Space and shape

4px base

Spacing scale

4, 8, 12, 16, 24, 32, 48, 64, 96. Inside a component use 4–16. Between components use 16–32. Between sections use 48–96. Nothing in between.

Radius carries hierarchy

3px on chips, ticks and inputs. 6px on buttons and fields. 10px on panels. Pills only on toggles that behave like switches. One radius on everything is a smell, not a system.

Elevation

Exactly two levels: canvas and surface, separated by a 1px line rather than a shadow. Modals get a scrim at 55% canvas. Nothing else lifts.

Motion

160ms, cubic-bezier(.2,.6,.3,1), and only in response to a tap. The one exception is the gauge marker, which slides to position on first load so the band registers before the value does.

Accessibility

Non-negotiable

Contrast

Ink on canvas is 13.4:1. Ink 2 clears 5.5:1 for small text. Ink 3 is for 12px non-essential labels only and never carries meaning alone. Domain colours are used for text only on their matching tint.

Never colour alone

Around 1 in 12 men has a colour vision deficiency, and this app is built for men. Every domain has a label, every mood has a height and a word, every band has a number underneath it.

Targets and focus

44×44px minimum on anything tappable, including the mood scale's narrowest bar. Focus rings are a 2px solid mind-blue at 2px offset, visible in both themes.

Reduced motion

The gauge marker's entry animation is the only thing that moves on its own, and it is disabled entirely under prefers-reduced-motion.
