# CI and build automation

`.github/workflows/openwiki-update.yml` runs on `workflow_dispatch` or daily at `0 8 * * *` on Ubuntu. It checks out full history because OpenWiki update mode needs the prior documented commit, sets up Node `22`, installs global `openwiki@0.3.1`, `mermaid@11.16.0`, and `jsdom@29.1.1`, then runs `openwiki code --update --print`. The job has `contents: write` and `pull-requests: write`. Its runtime environment names are `OPENWIKI_PROVIDER`, `OPENROUTER_API_KEY`, `OPENWIKI_MODEL_ID`, `OPENWIKI_LANGSMITH_API_KEY`, `LANGSMITH_API_KEY`, `LANGCHAIN_PROJECT`, and `LANGCHAIN_TRACING_V2`; values come from configuration or repository secrets and are not documented here.

The final step uses `peter-evans/create-pull-request` to create/update branch `openwiki/update`. Its `add-paths` are `openwiki`, `AGENTS.md`, `CLAUDE.md`, and `.github/workflows/openwiki-update.yml`; commit and title are `docs: update OpenWiki`, and the exact body is `Automated OpenWiki documentation update.\n\nThis PR was generated by the scheduled OpenWiki workflow.` Missing provider/API secrets can fail generation, shallow history can produce an empty change summary, and missing contents/PR write permissions can prevent publication. Changes to workflow permissions, pinned actions, model/provider variables, or added paths alter the documentation supply chain and should be reviewed as CI changes.

`tools/scripts/eas-build-post-install.mjs` is invoked by the Expo package's `eas-build-post-install` script with workspace and project roots. If the workspace root already has `node_modules`, it exits successfully; otherwise it symlinks the project's `node_modules` directory at the workspace root. This patches Nx Expo/EAS workspace resolution and should be changed together with `apps/app/package.json` or EAS build behavior.

These automation surfaces do not change runtime application behavior directly, but they affect generated wiki artifacts and release builds. Validate workflow YAML and the EAS hook with repository lint/typecheck plus the relevant Expo/EAS build path; do not test production automation by exposing credentials locally.
